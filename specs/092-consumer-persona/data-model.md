# Phase 1 — Data Model

**Feature**: 092 Consumer Persona and Nav Tidy
**Branch**: `092-consumer-persona`

This document defines the persistent entities, transport DTOs, invariants, and state transitions introduced by this feature. Types shown use C# 13 syntax with nullable reference types enabled. File naming and placement follow existing Sorcha conventions (`Sorcha.Tenant.Models/Persona/` for shared models; `Sorcha.Tenant.Service/Data/Entities/` for EF entities).

---

## 1. Persistent entity

### `PlatformUserPersona`

Lives in the Tenant Service PostgreSQL database. Exactly one row per `PlatformUser`. Row is created lazily on first `PUT /me/persona`. Row is hard-deleted atomically with the owning `PlatformUser` via an EF cascade rule.

```csharp
namespace Sorcha.Tenant.Service.Data.Entities;

public sealed class PlatformUserPersona
{
    public Guid PlatformUserId { get; set; }             // PK, FK → PlatformUser.Id

    public byte[] CiphertextBlob { get; set; } = default!;  // XChaCha20-Poly1305 AEAD ciphertext
    public byte[] Nonce { get; set; } = default!;           // 24 bytes
    public string WrappedKeyRef { get; set; } = default!;   // opaque handle used by Wallet Service

    public int SchemaVersion { get; set; } = 1;

    public DateTime CreatedAt { get; set; }
    public DateTime UpdatedAt { get; set; }

    // Navigation
    public PlatformUser PlatformUser { get; set; } = default!;
}
```

### EF configuration

```csharp
public sealed class PlatformUserPersonaConfiguration : IEntityTypeConfiguration<PlatformUserPersona>
{
    public void Configure(EntityTypeBuilder<PlatformUserPersona> b)
    {
        b.ToTable("platform_user_personas");
        b.HasKey(x => x.PlatformUserId);

        b.Property(x => x.CiphertextBlob).IsRequired();
        b.Property(x => x.Nonce).IsRequired().HasMaxLength(24);
        b.Property(x => x.WrappedKeyRef).IsRequired().HasMaxLength(256);
        b.Property(x => x.SchemaVersion).IsRequired();
        b.Property(x => x.CreatedAt).IsRequired();
        b.Property(x => x.UpdatedAt).IsRequired();

        b.HasOne(x => x.PlatformUser)
         .WithOne()
         .HasForeignKey<PlatformUserPersona>(x => x.PlatformUserId)
         .OnDelete(DeleteBehavior.Cascade);                  // FR-007a cascade
    }
}
```

### Migration handling

**Do not add a new incremental migration.** The schema addition is folded into the existing Tenant Service initial setup migration in `src/Services/Sorcha.Tenant.Service/Data/Migrations/`. This matches the pre-release squash rule (`feedback_migration_squash` memory). The task list generated by `/speckit.tasks` must name the exact file to edit.

## 2. Plaintext schema (server-side only)

The ciphertext in `PlatformUserPersona.CiphertextBlob` decrypts to a JSON document serialised from `PersonaAttributesV1`. This type is never stored in the database and never exposed over the wire in plaintext — it is the intermediate shape between encryption and the read/write APIs.

```csharp
namespace Sorcha.Tenant.Models.Persona;

public sealed record PersonaAttributesV1
{
    public string? GivenName { get; init; }
    public string? FamilyName { get; init; }
    public string? FullName { get; init; }
    public DateOnly? DateOfBirth { get; init; }

    public IReadOnlyList<PersonaEmail>   Emails        { get; init; } = [];
    public IReadOnlyList<PersonaPhone>   Phones        { get; init; } = [];
    public IReadOnlyList<PersonaAddress> Addresses     { get; init; } = [];
    public IReadOnlyList<string>         Nationalities { get; init; } = [];  // ISO 3166-1 alpha-2
}

public sealed record PersonaEmail(string Value, bool IsDefault, string? Label = null);

public sealed record PersonaPhone(
    string Value,
    bool IsDefault,
    string? Label = null,
    PersonaPhoneKind? Kind = null);

public enum PersonaPhoneKind { Mobile, Home, Work }

public sealed record PersonaAddress(
    string Line1,
    string? Line2,
    string City,
    string? Region,
    string PostalCode,
    string Country,           // ISO 3166-1 alpha-2
    bool IsDefault,
    string? Label = null);
```

### Invariants (enforced on write)

| # | Invariant | Enforcement point | Error code |
|---|---|---|---|
| I-1 | For each of `Emails`, `Phones`, `Addresses`, `Nationalities`, if the list is non-empty, exactly one entry has `IsDefault = true`. If zero marked, promote the first entry automatically (not an error). If more than one marked, reject. | `PersonaService.Update` | `multiple_defaults` |
| I-2 | Each list is capped at 5 entries. | `PersonaService.Update` (before encryption) | `list_cap_exceeded` (includes offending list name) |
| I-3 | Each `PersonaEmail.Value` matches RFC 5322 basic shape (FluentValidation `EmailAddress` rule). | FluentValidation on the request DTO | `invalid_email` |
| I-4 | Each `PersonaPhone.Value` is E.164. | FluentValidation regex | `invalid_phone` |
| I-5 | `PersonaAddress.Country` and each `Nationalities[i]` are ISO 3166-1 alpha-2 (two uppercase letters, against an allowlist loaded at startup). | FluentValidation | `invalid_country_code` |
| I-6 | `FullName` is only used as a read-side fallback when both `GivenName` and `FamilyName` are null. Write-side validation does not forbid providing all three. | Read-side resolver | n/a |
| I-7 | `SchemaVersion` on the stored row equals 1 in this feature. Future migrations must not break the v1 read path. | Write path | `schema_version_unsupported` |

## 3. Read-side DTOs (wire shape)

These types are shared between the Tenant endpoint and the `IPersonaClient` HTTP client. They live in `Sorcha.Tenant.Models/Persona/`.

```csharp
namespace Sorcha.Tenant.Models.Persona;

public sealed record PersonaAttribute<T>(
    T Value,
    PersonaAttributeSource Source,
    string? VerifiedBy,            // null in v1 (always SelfAsserted)
    DateTime LastUpdated);

public enum PersonaAttributeSource
{
    SelfAsserted = 0,
    VerifiedCredential = 1         // not used in v1, reserved for follow-up
}
```

### `PersonaReadModelV1` — the shape returned by `GET /me/persona`

```csharp
public sealed record PersonaReadModelV1
{
    public PersonaAttribute<string>?       GivenName    { get; init; }
    public PersonaAttribute<string>?       FamilyName   { get; init; }
    public PersonaAttribute<string>?       FullName     { get; init; }
    public PersonaAttribute<DateOnly>?     DateOfBirth  { get; init; }

    public PersonaAttribute<PersonaEmail>?   DefaultEmail   { get; init; }
    public IReadOnlyList<PersonaEmail>       AllEmails      { get; init; } = [];

    public PersonaAttribute<PersonaPhone>?   DefaultPhone   { get; init; }
    public IReadOnlyList<PersonaPhone>       AllPhones      { get; init; } = [];

    public PersonaAttribute<PersonaAddress>? DefaultAddress { get; init; }
    public IReadOnlyList<PersonaAddress>     AllAddresses   { get; init; } = [];

    public PersonaAttribute<string>?         DefaultNationality { get; init; }
    public IReadOnlyList<string>             AllNationalities   { get; init; } = [];
}
```

**Consumption pattern**:
- `SorchaFormRenderer` / `PersonaAutofillResolver` consumes `Default*` for autofill matching.
- `Profile.razor` consumes `All*` for the management UI.
- Profile page uses `PersonaAttribute<T>.LastUpdated` to render "Last updated ..." hints.

### `PersonaReadOptions` — the delegation-ready surface

```csharp
namespace Sorcha.Tenant.Models.Persona;

public sealed record PersonaReadOptions
{
    public string ActingAs { get; init; } = "self";
}
```

In v1 the only valid value is `"self"`. Any other value returns 400 `actingAs_not_supported`. The parameter is mandatory on the `IPersonaService` contract from day one so that adding delegation later is purely a value-space change (see FR-034, FR-035 and research Decision 3).

## 5. State transitions

### Persona row lifecycle

```
(no row)
   │
   │  first PUT /me/persona (succeeds)
   ▼
[row created]
   │
   │  PUT  — full replace
   │  PATCH — partial replace
   │  both update Nonce + CiphertextBlob + UpdatedAt
   ▼
[row updated]
   │
   ├──  DELETE /me/persona  ─►  (no row)      [idempotent]
   │
   └──  PlatformUser.Delete  ─►  (no row)     [EF cascade, atomic]
```

### Field provenance lifecycle during form rendering

```
(empty field)
    │
    │  resolver applies persona value, autofill=ON
    ▼
[autofilled — cream tint + self tick + accessible description]
    │
    ├── user edits field  ─►  [user-entered — no tint, no tick, no a11y description]
    │
    ├── user clears field via Review  ─►  (empty field)
    │
    └── user clicks Clear all        ─►  (empty field)
```

Once a field transitions out of the `autofilled` state it cannot re-enter it within the same form session, even if the user retypes the exact persona value. This is enforced by removing the field path from the `_personaFilledPaths` set in `SorchaFormRenderer`.

## 6. Relationships

- `PlatformUserPersona` → `PlatformUser` : one-to-one, required. Cascade delete. FK on `PlatformUserId`.
- No relationship to `Wallet` at the EF level — Tenant Service does not own the wallet model. Wallet address is resolved via `IWalletServiceClient` at request time (existing lookup path), not stored on the persona row.

## 7. Scope and scale

| Metric | Value |
|---|---|
| Rows per user | 0 or 1 |
| Ciphertext size bound (plaintext + auth tag + overhead) | ~5 KB (dominated by 5 addresses + labels). Plenty of headroom under any reasonable row size. |
| Write rate | Low — user profile edits only, not hot-path |
| Read rate | One read per form open per session, mitigated by session-lifetime client cache |
| Expected latency (cold read) | < 500 ms p95 from form-interactive (SC-006a) |
| Expected latency (warm read) | Indistinguishable from first render frame |
