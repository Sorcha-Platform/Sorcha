# Data Model: Service-to-Service mTLS Workload Identity (F191)

No database changes. `ServicePrincipal` (Tenant Postgres) is unchanged — the certificate maps
onto it. All new state is filesystem material plus configuration.

## Identities

### SpiffeId (value object, `Sorcha.WorkloadIdentity`)

`spiffe://{trustDomain}/service/{clientId}`

| Field | Rule |
|---|---|
| `trustDomain` | = installation name (`JwtSettings:InstallationName`, default `sorcha`); lowercase; same source as JWT issuer/audience namespace — never independently configured |
| `clientId` | exact ServicePrincipal `ClientId` (e.g. `service-blueprint`); no normalisation |
| Comparison | full-URI Ordinal equality; parse rejects other schemes/shapes |

### Service ↔ certificate map (v1 issuance universe)

| ClientId | DNS SAN (compose hostname) |
|---|---|
| service-blueprint | blueprint-service |
| service-wallet | wallet-service |
| register-service | register-service |
| service-peer | peer-service |
| validator-service | validator-service |
| tenant-service | tenant-service |
| service-haip | haip-service |
| service-verifier | sorcha-verifier *(confirm at implementation)* |

## Certificate material (per-deploy directory, gitignored)

```text
config/workload-certs/
├── ca/
│   ├── ca.pfx            # Workload CA private key + cert (CLI-only; never mounted into services)
│   └── bundle.pem        # PUBLIC trust bundle: 1 root normally, 2 during rotate-ca overlap
├── services/
│   └── {client_id}.pfx   # leaf: private key + cert; mounted ONLY into its own service
└── server/
    └── tenant-service.pfx  # mTLS listener server cert (DNS SAN tenant-service), CA-issued
```

| Artifact | Algorithm | Lifetime (default) | SANs |
|---|---|---|---|
| Workload CA | EC P-256, self-signed, CA=true pathlen 0 | 5 years | — |
| Service leaf | EC P-256, CA-signed, digitalSignature, EKU clientAuth | 2 years | URI = SpiffeId, DNS = compose hostname |
| Tenant server cert | EC P-256, CA-signed, EKU serverAuth | 2 years | DNS = tenant-service |

Renewal threshold default: 30 days. Revocation: operational (re-issue + recreate), no CRL/OCSP
in v1 (documented trade-off, research D5).

## Configuration keys (canonical constants in `WorkloadIdentityConfig`)

### Client side (every service)

| Key | Meaning | Default |
|---|---|---|
| `ServiceAuth:ClientCertificate` | PFX file path **or** base64 PKCS#12; presence activates cert mode | unset (secret mode) |
| `ServiceAuth:ClientCertificatePassword` | PFX password | unset |
| `ServiceAuth:TrustBundle` | PEM bundle path for server-cert pinning | unset |
| `ServiceAuth:MtlsTokenAddress` | mint base address in cert mode | `https://tenant-service:8443` |

### Server side (Tenant)

| Key | Meaning | Default |
|---|---|---|
| `ServiceAuth:Mtls:ServerCertificate` (+`Password`) | listener server PFX; presence (with bundle) activates the listener | unset |
| `ServiceAuth:Mtls:TrustBundle` | PEM bundle for client-chain validation | unset |
| `ServiceAuth:Mtls:Port` | listener port | 8443 |
| `ServiceAuth:DisableSharedSecrets` | refuse secret-based service auth platform-wide | `false` |

### Observability

| Key | Meaning | Default |
|---|---|---|
| `WorkloadIdentity:ExpiryWarningDays` | Degraded window for health check; CLI status/renew threshold | 30 |

### Compose env vars (`.env`, generated by installer)

`WORKLOAD_CERT_PASSWORD` (new). The 8 `*_SERVICE_SECRET` vars remain (coexistence).

## State transitions

### Credential resolution (client)

`ServiceAuth:ClientCertificate` set → cert mode (unreadable ⇒ startup failure; never secret
fallback). Unset → legacy secret mode, untouched.

### Mint decision (server, `client_credentials`)

```
secret present?
├─ yes → DisableSharedSecrets? → refuse (explicit error) | else legacy Argon2id path (unchanged)
└─ no  → connection has chain-validated client cert?  (TLS layer already enforced trust/expiry)
         ├─ no  → refuse (missing credential)
         └─ yes → SpiffeId(SAN) == expected(installation, client_id)?
                  ├─ no  → refuse (identity mismatch, log both)
                  └─ yes → principal exists ∧ Active? → scope intersection → mint (identical token)
```

### CA rotation

`Active(CA₁)` → `rotate-ca` → `Overlap(bundle=[CA₂,CA₁], leaves re-issued under CA₂)` →
container recreates → `rotate-ca --complete` → `Active(CA₂)` (CA₁ leaves now refused).
